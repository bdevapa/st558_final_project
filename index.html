Introduction

The data comes from Banking Dataset - Marketing Targets. This is picked up from publicly available research data UCI Machine Learning using random sampling plus a few additional columns are introduced in Kaggle data.

In Project 2, I explored this data with an interactive Shiny app. The goal of this (final) project is to predict y y is a categorical outcome of the campaign, therefore we will be working on a binary classification problem.

Client Traits (column names in the data set):

bank client data:

  1. age (numeric)
  2. job : type of job (categorical: “admin.”,“unknown”,“unemployed”,“management”,“housemaid”,“entrepreneur”,“student”,“blue-collar”,“self-employed”,“retired”,“technician”,“services”)
  3. marital : marital status (categorical: “married”,“divorced”,“single”; note: “divorced” means divorced or widowed)
  4. education (categorical: “unknown”,“secondary”,“primary”,“tertiary”)
  5. default: has credit in default? (binary: “yes”,“no”)
  6. balance: average yearly balance, in euros (numeric)
  7. housing: has housing loan? (binary: “yes”,“no”)
  8. loan: has personal loan? (binary: “yes”,“no”)

related with the last contact of the current campaign:

  1. contact: contact communication type (categorical: “unknown”,“telephone”,“cellular”)
  2. day: last contact day of the month (numeric)
  3. month: last contact month of year (categorical: “jan”, “feb”, “mar”, …, “nov”, “dec”)
  4. duration: last contact duration, in seconds (numeric)

other attributes:

  1. campaign: number of contacts performed during this campaign and for this client (numeric, includes last contact)
  2. pdays: number of days that passed by after the client was last contacted from a previous campaign (numeric, -1. means client was not previously contacted)
  3. previous: number of contacts performed before this campaign and for this client (numeric)
  4. poutcome: outcome of the previous marketing campaign (categorical: “unknown”,“other”,“failure”,“success”)

Output variable (desired target):

  1. y - has the client subscribed a term deposit? (binary: “yes”,“no”)

There are 31,647 observations in the training data. 5 fold CV splits them into 5 folds of about 6,330 observations each (or 6329 in some folds). In each of the 5 iterations, the model is fit on 4 folds (about 25,300 observations) and evaluated on the remaining fold which is the validation fold. Each fold serves as the validation fold exactly once. The log-loss is averaged for these 5 iterations.

CV helps to select the hyperparameters that are not influenced by specific subset of training data. Instead all of the training data is used for both fitting and evaluatiing the model in different iterations and for each combination of the tuning-grid/hyperparameter selection

The test set is not used in CV process.

Metric for selecting the best model from each family

I will go with log-loss function. Basically in a classification problem we have to maximize the likelihood of correctly estimating the outcome which translates to minimizing negative likelihood function aka log-loss function. One other option considered is accuracy - however the share of subscribers is about 12%. Therefore, a model that learns to classify every customer as “no” gets it right 88% of the times which is not meaningful. An 88% accuracy would only be meaningful if the outcome classes were balanced.

bank_metrics <- metric_set(mn_log_loss)

Classification tree

A classification tree falls under the category of supervised learning models and isi used when the response variable is categorical.

The idea behind a tree-based model is to split the predictor space into different regions and make a prediction for reach region. Unlike logistic regression, the predictions in adjacent regions do not necessarily have to be close to each other.

One of the interesting things we noticed during our EDA was that the subscription rate went from approximately 10% to 42% around the age of 60. A tree-based model could potentially capture this pattern by splitting the data based on age.

How does the model make predictions?

In a regression tree, as we saw in HW10, the prediction is the mean of a response variable in a given region. In a classification tree, however, the prediction is the most prevalent class in that region.

Since we are using log-loss as our metric, we are interested in the probability of a client subscribing to a term deposit. This probability can be obtained by looking at the proportion of clients who subscribed within a given terminal node.

How does the tree fit?

The fitting is done by recursive binary splitting, which is greedy; it picks the best split that minimizes loss at each step without looking ahead. At each step it tries every predictor and every possible cut point, and chooses the split that makes the two new regions as close to all yes or all no as possible, then repeats this within each new region.

What is Pruning?

If we keep splitting, the tree will grow very large and overfit the training data. Trees are usually grown large first and then pruned back using cost-complexity pruning which is controlled by the cost_complexity tuning parameter.

What are the other tuning parameters?

The other tuning parameter I use this tree_depth, which sets the maximum depth of the tree. The final tree is limited by the stricter of cost_complexity or tree_depth Another parameter, min_n, is the minimum number of observations a node needs before it can split. I will leave it as the default of 20.

I tune cost_complexity and tree_depth together using a grid of 5 values each, which gives 25 combinations. Each combination is fit using the 5-fold CV described above, and the one with the lowest average log-loss is selected

Fitting the classificaiton tree

tree_spec <- decision_tree(cost_complexity = tune(), tree_depth = tune()) |>
  set_engine("rpart") |>
  set_mode("classification")


tree_workflow <- workflow() |>
  add_recipe(bank_recipe) |>
  add_model(tree_spec)


tree_grid <- grid_regular(cost_complexity(), tree_depth(), levels = 5)

tree_results <- tree_workflow |>
  tune_grid(resamples = bank_folds, grid = tree_grid, metrics = bank_metrics)

# arrange the 25 trees by the mean value of mn_log_loss in ascending order 
collect_metrics(tree_results) |>
  arrange(mean)
